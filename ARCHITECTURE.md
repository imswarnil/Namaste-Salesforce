# The theme's own architecture

**NSDS — the Namaste Salesforce Design System — owns how things LOOK. This
file is what the theme owns: how Ghost is wired.**

Everything in `assets/css/nsds/`, `assets/js/nsds/` and `partials/nsds/` is
VENDORED and generated by `yarn design:sync`. Never edit it; change
`NS-Design-System` and re-sync. What follows is the part that is genuinely
this theme's, and it exists because Ghost works a particular way — no design
system can supply any of it.

If you are deleting theme code to move it onto NSDS, **these five are not
candidates.** They are not styling.

---

## 1 · `post.hbs` is a DISPATCHER, not a template

Ghost gives you exactly one `post.hbs` for every post on the site. This site
has seven kinds of post, and they are different *pages* — a lesson is a
reading player, a course is a sales page, a doc is a reference.

So `post.hbs` renders nothing itself. It reads the post's tags and dispatches:

```hbs
{{#post}}
  {{#has tag="documentation"}}     {{> "post-documentation"}}
  {{else has tag="#training-section"}} {{> "post-training-section"}}
  {{else has tag="#training-content"}} {{> "post-training"}}
  {{else has tag="#course"}}       {{> "post-course"}}
  {{else has tag="#lesson"}}       {{> "post-lesson"}}
  {{else has tag="#resource"}}     {{> "post-resource"}}
  {{else has tag="#blog"}}         {{> "post-blog"}}
  {{else}}                         {{> "post-default"}}
  {{/has}}
{{/post}}
```

**ORDER IS LOAD-BEARING.** `#training-section` is tested BEFORE
`#training-content`: a section overview is not a lesson, and matching the
lesson branch would render it inside the lesson player. Any new branch goes in
the position its specificity demands, not at the end.

**The fallback is not optional.** A post with none of these tags still has to
render, which is why `post-default` exists and why it is the same reading
surface a blog post gets.

`default.hbs` dispatches too, on the same tags — the chrome swaps between
`partials/header` (marketing bar) and `components/course-player-header`
(reading bar), and between `partials/footer` and `partials/footer-lesson`.

## 2 · JSON-LD is assembled as ONE `@graph`

`partials/jsonld/graph.hbs` emits a single
`<script type="application/ld+json">` holding a `@graph` array of linked
nodes — the pattern Google prefers, and the one Yoast and RankMath use.

- Site-wide base nodes (owner · website · navigation) always emit.
- Per-page nodes append after them, and **each per-page partial starts with a
  comma** because it is being concatenated into an array.
- Live: `Course` (+ `CourseInstance`, `hasPart` → lessons) for `#course`, and
  `LearningResource` (+ `VideoObject` for `#lesson-type-video`) for `#lesson`.

**Rules that will bite you:**

- Included in `<head>` BEFORE `{{ghost_head}}`.
- **Double-stache only.** `{{title}}` HTML-escapes quotes, which is what keeps
  the JSON parseable. `{{{title}}}` will emit a raw `"` and break the block.
- It is ADDITIVE to the JSON-LD Ghost already emits. The duplication is
  harmless and deliberate.

## 3 · Responsive images go through ONE partial

`partials/components/img.hbs`. Ghost generates the widths declared in
`package.json → config.image_sizes` (xxs 30 · xs 100 · s 300 · m 600 · l 1000
· xl 2000) at upload time; they cost nothing extra to serve.

```hbs
{{> "components/img" src=feature_image alt=feature_image_alt
    sizes="(min-width: 64rem) 24rem, 92vw" eager=true}}
```

- `sizes` is required in spirit: a wrong `sizes` is worse than none, because
  the browser picks confidently from it.
- `eager=true` on the ONE above-the-fold image per route — it also sets
  `fetchpriority="high"`. Everything else stays lazy. Above the fold,
  `loading="lazy"` is a pessimisation.
- **It is a plain `<img>`, deliberately not `<picture>`.** NSDS styles media
  with direct-child selectors (`.ns-chero__media > img`,
  `.ns-card__media > :where(img, video)`), and a `<picture>` wrapper silently
  drops every one of them. The gain would be a format; the cost would be the
  object-fit and aspect ratio on every card.

## 4 · The members form is a STATE MACHINE the theme has to supply

`assets/css/2-components/subscribe.css`, driven by
`partials/members/subscribe.hbs`.

Ghost's members script does exactly one thing to a `data-members-form`: it
puts `loading`, then `success` or `error`, on the FORM element. It does not
reveal a message, spin a spinner, or disable a button.

**The two message elements must stay SIBLINGS of the form** — they are
revealed with `~`. Nest them inside it and they are hidden permanently, which
is the bug this file was written to fix: five hand-rolled copies each had
messages marked `hidden` that nothing ever un-hid, so subscribing appeared to
do nothing at all.

There is ONE signup form in the theme. Every other place includes it.

## 5 · Icons are inline SVG, and that diverges from NSDS on purpose

`partials/icons.hbs` — 125 hand-drawn 24×24 icons dispatched by name.

```hbs
{{> icons name="arrow-right"}}
{{> icons name="rss" title="RSS feed"}}   {{!-- labelled, not aria-hidden --}}
```

NSDS was written against an icon FONT and styles glyphs by element
(`.ns-buybox__list i { … }`). This theme has no font in the render path, so
every one of those rules would miss. `assets/css/2-components/icon-bridge.css`
restates them for `.ns-icon`, with the upstream `file:line` on each so the two
can be diffed after a sync.

**The proper fix is upstream** — `i, .ns-icon` in NSDS's own selectors deletes
that bridge entirely. Until then it is the seam, and it must be re-checked
after every `yarn design:sync`:

```
grep -rnE '\.ns-[a-z-]+[^{]*\bi\b\s*[,{]' assets/css/nsds/components/css/
```

## Naming

| Path | What it is |
| --- | --- |
| `assets/css/nsds/` | NSDS stylesheets — **generated**, never edit |
| `assets/js/nsds/` | NSDS runtime — **generated**, never edit |
| `partials/nsds/` | NSDS partials (the inlined theme bootstrap) — **generated** |
| `assets/css/0-foundation` … `3-modules` | the theme's own layers |
| `partials/` (everything else) | the theme's own markup |

Class names are NSDS's `.ns-*` throughout. The theme does not invent a prefix:
a second namespace is how two products stop looking like one.
