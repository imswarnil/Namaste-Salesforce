Design system

Developer Console

The design language behind Namaste Salesforce. Everything on these pages is rendered from the theme's real assets/built/screen.css — if it looks right here, it looks right on the site.

Start Jump to components

The five rules

01

Hairlines, not shadows

One 1px border is the structuring device. Elevation means the border brightens to brand — never a floating lift.

02

Monospace is a material

Fira Code renders every index, duration, timestamp, status tag and kicker. Inter is for prose and headings only.

03

One signal colour

Brand blue is the only colour that means “interactive”. Status is a dot plus mono text, never a background wash.

04

Sharp, specific geometry

Cards 6px, buttons and inputs 4px. Pills are reserved for true pills — tags and pager controls.

05

Motion is instant

120–180ms plain ease-out. No spring, no bounce, no hover lift. The one exception is the float loop on illustrations.

The layers

The CSS is three layers, each with its own index.css. A later layer spends what the earlier ones declare, never the other way round. Feature styling lives in the component layer as site-*.css, imported last. 7 foundation pages, 38 component pages.

Layer 0

Foundation

Tokens, variables, mixins and helpers. Declares values, paints nothing.

Layer 1

Elements

Bare HTML — what a tag looks like with no class on it.

Layer 2

Components

The UI library. One file per component, each with its variants.

Naming

Every component follows one contract, so variants compose instead of multiplying classes:

PatternMeans
.ns-thingthe base — the smallest version that stands alone
.ns-thing--variantone axis at a time: size, shape, tone or state
.ns-thing__parta named internal part
.is-statea runtime state a script toggles
