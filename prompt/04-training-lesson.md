# Prompt — a TRAINING LESSON

> Paste `00-house-style.md` above this, then your brief.

You are producing a **training lesson** — one step inside one section of the
guided training, at `/training/{section}/{lesson}/`. This is the most
feature-rich content type on the site: it has four flavours, a video player that
adopts embeds out of your body copy, and clickable chapter timestamps.

Rendered by `partials/post-training.hbs` — the `.ns-reader` shell: section rail,
lesson, on-this-page rail.

---

## Where it lands and what the theme builds around you

```
/training/{section}/{lesson}/
```

| Region | Comes from |
| --- | --- |
| Left rail: every section and its lessons, current one marked | generated |
| Breadcrumb: Home › Training › {section} | theme (the lesson itself is deliberately not in the trail) |
| `<h1>` | Title |
| Lede | **Excerpt** |
| Type badge — Video / Exercise / Quiz / Article | the `#training-*` type tag |
| Duration chip | **`reading_time`, computed automatically.** There is no duration tag on training lessons — do not add one |
| "Free to read" / "Members only" | post **Visibility** |
| Video player frame | `#training-video` + the first embed in your body |
| Members gate panel | Visibility, when the reader lacks access |
| The lesson | **your body** |
| Prev / Next — **flowing across section boundaries** | generated by `training-nav.js`; becomes "Training complete" on the very last lesson |
| Questions & discussion | Ghost comments |
| Training newsletter band | theme |
| Right rail: on-this-page | your `<h2>`/`<h3>`s |

## Fields

| Field | Rule |
| --- | --- |
| **Title** | The step. "What is Salesforce?", "Set up a free Developer org", "Create a custom object", "Choosing the right tool". Imperative for exercises, plain phrase otherwise. No numbers. |
| **Slug** | `{section}-NN-{title-words}` — `build-01-create-a-custom-object`, `start-02-set-up-a-free-developer-org`. `NN` is for humans reading the admin list; **publish date is what orders it.** |
| **Excerpt** | Renders as the lede. One sentence, 15–30 words. What the reader will have done by the end. |
| **Feature image** | For `#training-video` this is the player **poster** — use a real frame from the video. Otherwise optional; it renders in a hairline frame. |
| **Publish date** | **The lesson's position within its section.** Ascending, spaced an hour apart. |
| **Visibility** | `public` for most of the training. `members` / `paid` where you gate. |

## Tags — exact, and in this order

```
TAGS: <Section Tag>, #training-content, #training-{type}
```

1. **The section tag** — public, first, identical to the parent section post's
   tag. This is what nests the lesson under `/training/{section}/`.
2. `#training-content` — required. Never also add `#training-section`; the
   router checks that first and would render this as an overview page.
3. **Exactly one type tag:**

| Tag | Badge | Use it for |
| --- | --- | --- |
| `#training-video` | Video | a lesson whose centre is a recording |
| `#training-article` | Article | reading and explanation |
| `#training-exercise` | Exercise | do-this-in-your-org, numbered steps |
| `#training-quiz` | Quiz | check-your-understanding questions |

Omitting all three falls back to "Article", but be explicit.

## The four flavours

Pick one and write it properly. The type tag sets a badge; the *body* has to
match it.

### `#training-article` — 600–1,200 words

```html
<h2>{The idea, stated as a claim}</h2>
<p>{Why it matters in an org.}</p>

<h2>{How it works}</h2>
<p>{The mechanics. Table or code block if it earns one.}</p>

<h2>{Where it goes wrong}</h2>
<p>{The failure mode, the real error text, the real limit.}</p>
```

### `#training-exercise` — 400–800 words, steps are the point

```html
<h2>What you're building</h2>
<p>{One paragraph. The artefact and roughly how long it takes.}</p>

<h2>Before you start</h2>
<ul><li>{Concrete prerequisites — an org, a completed step}</li></ul>

<h2>Steps</h2>
<ol>
  <li>{Real UI paths, in full: "Setup → Object Manager → New Custom Object".
      One action per step. Say what should appear on screen after it.}</li>
</ol>

<h2>Check it worked</h2>
<p>{An observable outcome. "The record saves and Industry shows Unknown."
   Never "you should now understand".}</p>

<h2>If it didn't</h2>
<p>{The two most likely mistakes and how to recognise each.}</p>
```

### `#training-quiz` — 5–8 questions

Use a `<h3>` per question and put the answer in a `<details>` block so the reader
can self-mark:

```html
<h2>Check what stuck</h2>
<p>{One line of framing. No score, no gamification.}</p>

<h3>Which field type stores a value you never want to recalculate?</h3>
<details>
  <summary>Show answer</summary>
  <p>A standard field with a stored value. A formula field recalculates on every
    read, so a historical figure written by a formula changes when its inputs
    change.</p>
</details>
```

Questions must have one defensible answer. No trick questions, and every answer
explains *why*, not just *which*.

### `#training-video` — the embed and the notes

**Put exactly one embed in the body.** `training-video.js` finds the first
YouTube, Vimeo or native `<video>` inside `.gh-content`, **moves it out of the
flow and into the hero player frame**, and discards the poster. So:

- Do not try to place the video "at the top" — position in the body is irrelevant.
- Do not add a second video; only the first is adopted and the rest sit awkwardly
  mid-article.
- Write real notes underneath. The video moves away and whatever is left *is* the
  page.

#### Chapter timestamps become seek buttons

Any **table cell** or **list item** whose entire text is a timestamp is turned
into a play button that seeks the hero player:

- Accepted: `0:00`, `12:34`, `1:02:03`, and the same in parentheses.
- The cell must contain **nothing but** the timestamp — `0:00 Intro` will not
  match. Put the timestamp in its own cell.
- Works for **YouTube and native `<video>` only.** Vimeo embeds are moved to the
  hero but cannot be seeked, so do not build a chapter table for a Vimeo lesson.

```html
<h2>Chapters</h2>
<table>
  <thead><tr><th>Time</th><th>What's covered</th></tr></thead>
  <tbody>
    <tr><td>0:00</td><td>Why the object needs to exist</td></tr>
    <tr><td>2:15</td><td>Creating it in Object Manager</td></tr>
    <tr><td>6:40</td><td>The fields, and the two we leave out</td></tr>
  </tbody>
</table>
```

Then: a short prose summary, any code shown on screen as a real `<pre><code>`
block (never as a screenshot), and the links referenced.

---

## Structure rules

- **Two `<h2>`s minimum** — the on-this-page rail hides below that.
- `<h2>`/`<h3>` only.
- No "Next lesson" link. Prev/Next is rendered, and it flows *across* section
  boundaries, so hand-written navigation will contradict it.
- At most two `.ns-note` callouts.
- Code blocks always carry `class="language-…"`.

## Worked example (`#training-exercise`)

```
─────────────────────────────────────────
TITLE:        Create a custom object
SLUG:         build-01-create-a-custom-object
EXCERPT:      Build the Project object from nothing, and decide what it is called
              before you decide what it stores.
TAGS:         Build, #training-content, #training-exercise
VISIBILITY:   public
PUBLISH:      2026-08-08 10:00   (relative order: 1 of 3 in "Build Your First App")
FEATURE IMAGE: none
─────────────────────────────────────────
BODY (paste into a Ghost HTML card):

<h2>What you're building</h2>
<p>A custom object called Project, with a label, a plural label and a record
  name that reads properly in a list view. Ten minutes. Everything else in this
  section hangs off it.</p>

<h2>Before you start</h2>
<ul>
  <li>A Developer org you can log into</li>
  <li>System Administrator on that org, which you have by default in a
    Developer org</li>
</ul>

<h2>Steps</h2>
<ol>
  <li>Click the gear icon, then Setup. Setup opens in a new tab.</li>
  <li>In Setup, go to Object Manager and click Create → Custom Object.</li>
  <li>Label: <code>Project</code>. Plural Label: <code>Projects</code>. Leave
    the API name as Salesforce fills it in.</li>
  <li>Record Name: <code>Project Name</code>, Data Type Text. This is the field
    that shows up as the link in every list view, so a Text name beats an
    auto-number here.</li>
  <li>Tick <strong>Allow Reports</strong>. You will want it in the last lesson
    of this section, and turning it on later means editing the object again.</li>
  <li>Save.</li>
</ol>

<h2>Check it worked</h2>
<p>Object Manager lists Project with API name <code>Project__c</code>. Open the
  App Launcher, search Projects, and you get an empty list view with a New
  button.</p>

<h2>If it didn't</h2>
<p>No Projects tab in the App Launcher is normal — a custom object has no tab
  until you make one, and the list view is still reachable by search. If Save
  failed, the Plural Label was probably left empty; it is required even though
  the form does not mark it.</p>

<div class="ns-note ns-note--info">
  <i class="ph ph-lightbulb ns-note__icon" aria-hidden="true"></i>
  <div class="ns-note__body">
    <p class="ns-note__title">Names are the hard part</p>
    <p>API names cannot be changed without breaking every reference to them.
      Spend the extra minute now.</p>
  </div>
</div>
```

## Self-check

Everything in `00-house-style.md`, plus:

- [ ] Section tag first, identical to the parent section's tag
- [ ] `#training-content` present; `#training-section` **absent**
- [ ] Exactly one `#training-*` type tag, and the body matches that flavour
- [ ] **No duration tag** — training lessons compute reading time
- [ ] Publish date set to the intended position within the section
- [ ] Video lesson → exactly one embed in the body, plus real notes below it
- [ ] Chapter timestamps alone in their cell, and not on a Vimeo lesson
- [ ] Exercise → has "Check it worked" with an *observable* outcome
- [ ] Quiz → every answer explains why
- [ ] Two or more `<h2>`s; no hand-written next-lesson link
