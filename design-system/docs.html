Foundations

The NS Design System, written down

How to install it, how the cascade is layered, what every token means, how motion, depth and breakpoints behave, and the rules that keep the two themes and the accessibility promise intact.

Introduction

NS Design System is the design system behind Namaste Salesforce — a Salesforce learning publication built on Ghost. The site, the course player, the training trail and this documentation all draw from the same stylesheet. It lives inside the theme repository at design-system/ and publishes to salesforce.imswarnil.com.

It is deliberately small: 53 plain SCSS partials compiled by dart-sass into a single screen.css. There are no mixins to learn, no CSS-in-JS and no build tooling required to consume it. The public API is two things:

  • Class names — .btn, .card, .quiz, .trail and friends, documented live in the component gallery and the sections gallery.
  • Custom properties — every colour, radius, shadow, duration and measure is a --token you can read or override.

What makes it a learning system rather than a generic kit: progress bars and rings, the lesson rail with done and locked states, prev/next lesson navigation, a CSS-only quiz, the training trail and the horizontal path are first-class components, not afterthoughts.

Installation

Option 1 — one link tag

Point at the hosted stylesheet and you are done. Both themes come along for free. The runtime is optional — it only adds the theme toggle, scroll-spy contents, copy buttons, the quiz tally and a toast.

<link rel="stylesheet" href="https://salesforce.imswarnil.com/dist/css/screen.min.css" />
<script src="https://salesforce.imswarnil.com/dist/js/nsds.js" defer></script>

Option 2 — build from source

The system is a folder of the Ghost theme repository.

git clone https://github.com/imswarnil/Namaste-Salesforce.git
cd Namaste-Salesforce/design-system
npm ci
npm run build    # sass → dist/css/screen.css + screen.min.css, copies fonts + nsds.js
npm run watch    # recompile on save
npm run serve    # static server at :4322

The compiled dist/ is committed on purpose, and CI fails on drift — what you see in the repository is byte-for-byte what the build produces.

The rem base

The system assumes html { font-size: 62.5% }, so 1rem = 10px. Every size is written against that base — 1.6rem is 16px. The reset sets this for you.

Fonts

Figtree is self-hosted as four woff2 subsets and referenced as url(../fonts/…) relative to the compiled CSS. If you copy dist/css/ somewhere, copy dist/fonts/ beside it.

Architecture

The manifest src/scss/screen.scss is the source of truth for the cascade. Each folder is a layer, and the @use order is the specificity strategy — later layers may override earlier ones, never the reverse.

LayerFolderPartials
0 — Abstracts0-abstracts/fonts, tokens. Design tokens and font faces only — no selectors that paint.
1 — Base1-base/reset, typography, content. Element defaults and the .gh-content article body.
2 — Layout2-layout/containers, header, footer. The frame, including the CSS-only mobile drawer and dropdowns.
3 — Components3-components/buttons, chips, badges, cards, avatars, forms, search, widgets, toc, filters, pagination, pager, alerts, tabs, accordion, tables, lists, progress, quiz, media, code, stats, pricing, testimonial, tooltip, empty.
4 — Templates4-templates/sections, home, blog, post, courses, course, lesson, training, trail, trainer, videos, newsletter, changelog, page, docs, archive, error.
5 — Utilities5-utilities/patterns, helpers. Background patterns and the few helpers allowed to win.

Partials are plain CSS in .scss files on purpose — no nesting, mixins or functions unless there is a real win. The folder answers where a rule lives; the manifest answers when it applies.

Deploy: pushes to main that touch design-system/ run the design-system GitHub Actions workflow — it rebuilds, proves dist/ has not drifted, stages the pages plus dist/ into _site/, writes the CNAME and publishes to GitHub Pages. The Ghost theme deploy excludes the folder, so the theme zip never carries it.

Design tokens

All values route through the custom properties in _tokens.scss. The raw colour ramps live on :root and never change; everything the system actually paints with is a semantic token, defined once for light and once for dark.

TokenRole
--bg / --bg-altPage background and the alternating section band.
--surface / --surface-altCards, widgets and other raised panels.
--border / --border-softHairlines; soft is for dividers that should whisper.
--text / --text-muted / --text-faintBody copy in three volumes.
--headingDisplay and heading ink.
--accent / --accent-strong / --accent-softThe one blue, its hover, and its tint.
--accent-contrastInk that sits on accent fills.
--header-bgThe translucent sticky header pane.
--code-bgInline code background.
--scrimDialog backdrop and overlays.
--success-ink / --warning-ink / --error-ink / --info-inkStatus text — the base hues fail AA on white, the inks do not.
--level-ink / --featured-inkCourse-level and featured chips. An intermediate course is neither a problem nor a risk, so these are not the warning ink wearing another name.

The rule for new values: tokens first. A new colour, radius, shadow or duration becomes a token in _tokens.scss, then components consume var(--token). No raw hex in components, ever.

Typography

The typeface is Figtree, one variable face covering weights 300–900 in normal and italic, self-hosted as four woff2 subsets (latin and latin-ext, each style). The same system stack Casper ships sits behind it so nothing flashes ugly while the font loads. Code takes --font-mono.

Display one

h1 · clamp(3.2rem, 5vw, 4.6rem) · 700

Heading two

h2 · clamp(2.4rem, 3.5vw, 3.2rem) · 700

Heading three

h3 · 2.1rem · 700

Heading four

h4 · 1.8rem · 700

Article body reads at 17.5px with a 1.7 line height.

.gh-content · 1.75rem · 400

Interface copy sits at 16px with a 1.6 line height.

body · 1.6rem · 400

Card excerpts and meta lines step down to 14.5px.

.card-excerpt · 1.45rem · 400
Kicker label.kicker · 1.2rem · 700 · 0.1em tracking

Headings are bold (700), tightly tracked, and balanced with text-wrap: balance. Hero titles push to 800. Long-form article content gets its full treatment from .gh-content — lists, blockquotes, tables, code blocks and figure captions are all styled there, and every card the Ghost editor can produce lands inside it.

Shape & depth

Radius

--radius-sm · 6px
--radius · 10px
--radius-lg · 16px
--radius-full · 999px

Buttons and inputs take --radius-sm; panels, callouts and code take --radius; cards, widgets, heroes and bands take --radius-lg; chips, badges, pills and progress bars take --radius-full.

Shadows

--shadow-sm
--shadow
--shadow-lg

Resting surfaces have a hairline border and no shadow. --shadow appears on hover; --shadow-lg belongs to things that float — dropdowns, dialogs, the browser frame, a featured pricing tier. In dark mode the shadows deepen and gain a faint light rim so edges still read on navy.

The container grammar

Every band is .outer (full bleed, page padding of max(4vmin, 20px)) wrapping .inner (centred, 1200px). .inner-narrow caps at the prose measure. Vertical rhythm comes from .section — clamp(4.8rem, 8vmin, 8rem) top and bottom — and .section-alt paints the band with --bg-alt so alternating sections breathe.

<section class="section section-alt outer">
  <div class="inner">
    <div class="section-head">
      <div>
        <span class="kicker">Courses</span>
        <h2>Start where you are</h2>
        <p>One line that sets the section up.</p>
      </div>
      <a class="section-more" href="/courses/">All courses</a>
    </div>
    …
  </div>
</section>

.section-head is the one heading pattern: kicker, title, a supporting line, and an optional "more" link that sits on the baseline at the right and wraps under on small screens.

Motion

One easing family, three durations. Every transition in the system is one of these; nothing invents its own curve.

TokenValueUse
--easecubic-bezier(0.2, 0, 0, 1)Default — colour, transform, opacity.
--ease-outcubic-bezier(0, 0, 0.2, 1)Things arriving: toasts, dropdowns, the live pulse.
--dur-fast150msHover colour and border changes.
--dur220msLifts, chevrons, drawer and dropdown reveals.
--dur-slow400msProgress bars filling, the trail drawing.
  • Animate transform, opacity and colour only. Never width, height, top or left — the progress bar's fill is the one exception, and it is a decorative width on a pseudo-element.
  • Hover is a 1–3px lift plus a shadow, never a scale, so text does not blur.
  • Reduced motion zeroes everything. The reset sets every animation and transition duration to 0.01ms under prefers-reduced-motion: reduce; the marquee stops and wraps; smooth scrolling turns off.

Elevation & z-index

Stacking is named so nothing guesses a number. Anything not in the table sits at auto.

TokenValueWhat sits there
--z-raised10Tooltips, the card's stretched link, the hero float.
--z-sticky100Sticky rails, the mobile lesson bar, the rail toggle.
--z-drawer290The mobile navigation drawer — just under the header.
--z-header300The sticky site header.
--z-modal400Dialogs (native <dialog> uses the top layer regardless).
--z-toast500Toasts and the skip link.

Breakpoints

Four width classes. Layouts are fluid between them; only the structural shifts below are pinned.

ClassWidthWhat changes
Compact< 600pxSingle column everywhere. Stepper labels collapse to the current step. Dialogs become bottom sheets. Definition grids stack.
Medium600 – 899pxTwo-up card grids. The header still uses the drawer (≤ 900px): the burger shows, navigation becomes a full-height panel, dropdown children render inline and indented.
Expanded900 – 1279pxFull navigation bar and dropdowns. Sidebars still fold under content at ≤ 1023px; the lesson rail becomes a <details> drawer and the sticky lesson bar shows. From 1024px the rail sits beside the article and can collapse via html[data-rail="closed"].
Wide≥ 1280pxThe lesson player grows its second column — the page's own table of contents. The training reader shows all three columns.

Media queries are written as max-width against the same four edges (600, 900, 1023, 1279) so a component never contradicts a template.

Icons

One drawing style, inline SVG, no icon font: a 24-unit box, 1.8 stroke, round caps and joins, fill="none", stroke="currentColor". Icons inherit the text colour of their parent and never carry their own hex.

SizeWhere
1.4remChips, crumbs, meta lines, kickers.
1.6remNavigation, buttons, list bullets, rail rows.
2.0remIcon buttons, alerts, section headings.
2.4remProp and stat tiles, empty states, the logo strip.

Decorative icons get aria-hidden="true"; an icon that is the whole control gets an aria-label on the button. Solid glyphs (the play badge, social marks) use fill="currentColor" and no stroke.

Interaction states

StateTreatment
EnabledResting face: hairline border on surfaces, muted ink on secondary text.
HoverCards and tiles lift 2–3px and take --shadow-lg; buttons darken to --accent-strong and lift 1px; links and rows turn --accent.
Focus:focus-visible draws a 2px --accent ring at 2px offset on everything — including radio-driven tabs, which forward focus to their label row.
Active / pressedThe lift returns to zero; no extra colour.
Current.is-current, .nav-current or aria-current="page": accent ink on an --accent-soft fill.
SelectedFilter buttons and pager pages invert: accent fill, contrast ink.
Done.is-done in rails, trails and steppers: a success tick replaces the number; text drops to faint.
Locked.is-locked: 55% opacity, faint lock icon, still readable.
Disabledaria-disabled="true" plus opacity: .5 and no hover; never display: none.
Right / wrongThe quiz paints a chosen option success or error and reveals the explanation with :has().

Theming

Both themes ship in the one stylesheet. The contract lives on the <html> element:

MarkupResult
<html>Follows the system preference (auto).
<html data-theme="light">Forced light.
<html data-theme="dark">Forced dark.

Apply the stored choice before first paint so there is no flash, then let nsds.js (or twelve lines of your own) handle the click:

<script>
  // In <head>, before the stylesheet paints:
  try {
    var t = localStorage.getItem("nsds-theme");
    if (t) document.documentElement.dataset.theme = t;
  } catch (e) {}
</script>
<button class="icon-btn" data-theme-toggle aria-label="Toggle color theme">…</button>

Retheme by overriding tokens after the stylesheet loads — start with --accent, --accent-strong, --accent-soft, the radii and the --brand-* ramp.

Maintenance rule: dark values are defined twice — once under html[data-theme="dark"] and once inside the prefers-color-scheme: dark block for html:not([data-theme]). CSS still has no way to say it once; keep the two blocks identical.

Accessibility

Contrast

PairRatio
--text on --bg (light)12.6 : 1
--text-muted on --bg (light)7.4 : 1
--accent-contrast on --accent (light)4.9 : 1
--text on --bg (dark)9.8 : 1
--accent on --bg (dark)6.1 : 1

All semantic ink and surface pairs meet 4.5:1 in both themes; status text always uses a *-ink token because the base hues do not. Icons and hairlines that carry meaning meet 3:1.

Touch targets

Buttons are 44px tall (36px for .btn-sm, which never stands alone), icon buttons 40px, drawer rows and rail rows full-width. Nothing interactive is smaller than 40 × 40px.

Keyboard

KeyAction
TabMoves through every control in DOM order; dropdowns open on focus-within.
Enter / SpaceActivates buttons, summaries and radio-driven tabs.
← →Move between tabs and quiz options (native radio behaviour).
EscCloses the mobile drawer, a dialog and fullscreen.

Structure

  • A skip link is the first focusable element on every page and targets #main.
  • One <h1> per page; headings never skip a level. Rails use <nav aria-label>; sidebars are <aside>.
  • Progress uses role="progressbar" with aria-valuenow; the quiz is a real <fieldset> with a <legend>.
  • Motion respects prefers-reduced-motion; colour scheme respects prefers-color-scheme.

Content & writing

  • Sentence case for headings, buttons and labels. Kickers are the only uppercase text.
  • Chip text comes from a tag's description, never its slug. #course-level-beginner described as "Beginner" renders as "Beginner"; no template hardcodes vocabulary.
  • Buttons start with a verb — "Start the course", "Join free", "Copy" — and say what happens, not "Submit".
  • Measure ≤ 60 characters for supporting copy; --measure keeps articles at about 72.
  • No exclamation marks. The tone is a trainer explaining, not a landing page shouting.
  • Numbers are tabular wherever they line up — stats, counters, durations, prices.

Conventions

  • Tokens first. New colours, radii, shadows and durations become custom properties in _tokens.scss before any component uses them.
  • Plain CSS in .scss files. No nesting, mixins or functions unless there is a real win — the API is class names and custom properties, not Sass.
  • Never reorder the manifest casually. The @use order in screen.scss is the cascade.
  • Build after every edit. npm run build — dist/ is committed and CI fails on drift.
  • Fonts stay siblings. Faces are referenced as url(../fonts/…) relative to the compiled CSS, so dist/css/ and dist/fonts/ must ship together.
  • State is a class, not a colour. .is-current, .is-done, .is-locked, .is-active, .is-open — templates toggle those; the stylesheet decides what they look like.

DESIGN.md files

Three Markdown files travel with the system so an AI coding tool — or a new contributor — can build with it without reading the SCSS. They follow the design-system skill format: tables over prose, exact values, cross-references at the top of each.

FileWhat it holds
DESIGN.mdToken reference — colours, type scale, shape, elevation, states, layout classes, motion, icons and the naming convention. Read this first.
design-guidelines.mdAccessibility requirements, touch targets, keyboard map, content rules, and do's and don'ts by category.
design-components.mdEvery component grouped by workflow — actions, input, navigation, containment, data display, feedback, learning — with measurements, states and markup.
llms.txtThe site described for machines: what exists, where, and how to consume it.
